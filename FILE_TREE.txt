HOW THE SITE IS ORGANIZED
--------------------------
- There is now a SINGLE set of root pages — index.html, links.html, projects.html —
  instead of one copy per theme. Each of these 3 files bundles all 4 visual themes'
  complete layout+markup as hidden/shown panels in one DOM, toggled via
  body[data-theme="a|b|c|d"]. No separate theme-a/ theme-b/ theme-c/ theme-d/
  folders exist anymore.
- CSS scoping convention (applies everywhere: these 3 pages, assets/css/project-themes.css,
  and Projects/Resume/tushar_supe_resume_2026.html): every theme's original selectors are
  mechanically prefixed with `body[data-theme="X"] ` (X = a/b/c/d). `:root{}` becomes
  `body[data-theme="X"]{}` (CSS vars), and shared/global rules (`html{}`, `*{}`, @keyframes,
  @font-face, @page) are left unscoped since they're identical/global across all 4 themes.
  @media blocks are scoped by recursing into their body. This is the ONE mechanical
  pattern used site-wide — keep using it for any future theme work.
- Theme selection: an inline script (identical on every page) reads localStorage key
  "theme" (falls back to 'd' if unset/invalid), sets body[data-theme], and defines
  window.switchTheme(next) which cycles a -> b -> c -> d -> a and persists the choice.
  It's wired to a deliberately inconspicuous control: a tiny low-contrast dot
  (class="corner-mark", aria-hidden, no visible label) fixed to the bottom-right
  corner of every page, with real padding for an actual click target.
- Shared, non-themed resources live at the repo root and are referenced via relative
  paths: images/, assets/ (fonts, legacy main.css/project.css, JS — unused by the
  current site — plus the new assets/css/project-themes.css, which IS used by every
  project detail page), Projects/<name>/ media files (thumbnails, screenshots, videos),
  and Projects/Resume/ (resume HTML + PDF — one shared file, theme-aware via the same
  scoping convention, text content unchanged from before).
- Project detail pages: one HTML file per project (DOM/content is identical across
  themes — only CSS differs), living at Projects/<snake_case_name>/<snake_case_name>.html.
  All 8 project folders were renamed from PascalCase/MixedCase to snake_case to match
  this convention. Each project page links assets/css/project-themes.css (the merged,
  theme-scoped stylesheet) and carries the same inline theme script + corner-mark dot.

MAINTENANCE NOTES
-------------------
- Adding a new personal project: add its media to Projects/<snake_case_name>/, create
  Projects/<snake_case_name>/<snake_case_name>.html linking assets/css/project-themes.css
  ("../../assets/css/project-themes.css") and the shared avatar favicon
  ("../../images/avatar.jpg"), and copy in the same inline theme script + corner-mark dot
  used by every other project page. Add a tile to projects.html AND a featured card to
  index.html, each inside all 4 theme-panel divs (<div id="theme-a-root">...</div>, etc.)
  so the new project shows up under every theme.
- Updating the resume: edit Projects/Resume/tushar_supe_resume_2026.html — one shared
  file read by every theme. Its <style> block has 4 scoped theme variants (same
  body[data-theme="X"] convention as everywhere else); the resume's HTML structure/text
  is NOT duplicated per theme (scoped-CSS-only, not full panel-bundling — the resume is a
  single-column document where only color/type tokens change per theme, so bundling 4
  copies of the full text would add risk/maintenance cost for no layout benefit).
- Changing/adding a visual theme: find its selectors in index.html / links.html /
  projects.html / assets/css/project-themes.css / the resume's <style> block — each
  theme's rules are grouped under a "/* ===== THEME X ===== */" comment and scoped via
  body[data-theme="X"] . Keep using that exact scoping convention for any new rules.
- There is no more switch-theme.ps1 / build step — the default active theme is whatever
  localStorage last recorded, falling back to 'd' (Cobalt Dark) for first-time visitors.
